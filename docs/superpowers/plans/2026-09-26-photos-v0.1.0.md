# com_xdecarophotos v0.1.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the first usable `com_xdecarophotos` milestone for Joomla 6.1.3+ with secure upload, Core references, manual crop, Avatar/Fototessera variants, backend Gallery, public consumer service, Core UI integration, diagnostics, tests, and installable package `pkg_xdecarophotos`.

**Architecture:** `com_xdecarophotos` owns photo files, metadata, variants, crop state, Gallery and Photo Studio behavior. Cross-component ownership/context uses Core 2.1.0 `EntityReference`; consumers never query Photos tables or derive storage paths. Generic UI is loaded from Core `AssetService`; Photos keeps only photo-specific CSS/JS.

**Tech Stack:** Joomla 6.1.3+, PHP supported by Joomla 6.1.3+, MySQL/MariaDB through Joomla Database API, Joomla MVC/Web Asset Manager/ACL/CSRF, `xdecaro\Core` 2.1.0, browser `getUserMedia`, Canvas APIs, PHPUnit/PHP test harness plus repository smoke scripts.

**Spec:** `docs/superpowers/specs/2026-09-26-photos-component-design.md`

## Global Constraints

- Runtime target is **Joomla 6.1.3 and later**. Do not add Joomla 4/5 compatibility unless explicitly requested and verified.
- Component identifier: `com_xdecarophotos`.
- Package identifier: `pkg_xdecarophotos`.
- Database prefix: `#__xdecarophotos_*`.
- Canonical PHP namespace: `xdecaro\Component\Photos`.
- Core minimum: **2.1.0**.
- New Core usage must use canonical lowercase `xdecaro\Core` namespace.
- No new global UID registry; owner/context references use Core `EntityReference(component, entity, id)` semantics.
- Allowed dependency direction: `Photos -> Core`; never `Core -> Photos`.
- Photos must not query private tables of People, Membership, Organizations, Competitions, or any other consumer.
- Original image is always preserved; crops/formats are variants.
- No biometric identity recognition and no persisted face biometric data.
- Every write path must enforce Joomla ACL + CSRF + input/file validation.
- Shared generic UI must use Core `AssetService` and `.xdecaro-*` primitives; Photos-specific CSS/JS is limited to image workflows.
- Mobile primary workflows must not require horizontal scrolling.
- Development version starts at `0.1.0`; never publish different ZIP contents with the same released version.

## Review Focus

1. **Malformed cross-component reference** — reject incomplete/invalid owner or partially-filled context without touching storage or database; covered in Task 2 tests.
2. **File masquerading as image** — reject extension/MIME mismatches and unsupported decoded image content; covered in Task 3 tests.
3. **Primary-photo race/integrity** — setting one photo primary must leave exactly one primary for the same owner/type/context; covered in Task 4 tests.
4. **Browser camera unavailable or denied** — Photo Studio must remain fully usable through upload and manual crop; covered in Task 7 browser tests.
5. **Deletion with dependent variants** — deleting/deactivating a photo must not leave orphaned files/rows or silently remove unrelated external entities; covered in Task 5 tests.

## Deferred after v0.1.0

These remain intentionally outside this implementation plan:

- automatic face-centering library integration beyond a non-blocking browser capability spike;
- identity/biometric recognition;
- automatic background removal/replacement;
- complex player-card/figurina graphic template engine;
- public album portal and mass moderation;
- migration of People/Membership/Organizations/Competitions fields to Photos until `PhotoService` v0.1.0 is installed and verified.

The next integration plan should migrate one consumer at a time, starting with People, through the public Photos service only.
